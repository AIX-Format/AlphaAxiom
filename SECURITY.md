# Security Model

This document covers the security posture of the Money Machine desktop
client (the `money-machine/` Tauri app). It is the most exposed surface
in the AlphaAxiom stack because it runs on user laptops, holds exchange
credentials, and can place real trades. Cloud-side components (the
Cloudflare Worker, the dashboard, the Telegram bot) have their own
threat models and are out of scope here.

## Trust boundaries

```
+---------------------+    Tauri invoke()     +---------------------+
|  Next.js frontend   | --------------------> |   Rust shell        |
|  (WebView)          | <-------------------- |   (src-tauri/)      |
+---------------------+    JSON result        +----------+----------+
                                                         |
                                       authenticated TCP | 127.0.0.1
                                       JSON-line wire    |
                                                         v
                                              +----------+----------+
                                              |  Python sidecar     |
                                              |  (src-python/)      |
                                              |  - ccxt -> exchanges|
                                              |  - Gemini API       |
                                              +----------+----------+
                                                         |
                                            HTTPS to     |
                                            third-party  v
                                            services
```

Three trust boundaries matter:

1. **Frontend to Rust shell.** Crossed by Tauri's IPC. Mediated by the
   Tauri ACL (`src-tauri/capabilities/default.json`) and the
   Content-Security-Policy. The frontend is treated as semi-trusted:
   it is our code but it loads in a WebView that can execute any
   script the CSP allows.
2. **Rust shell to Python sidecar.** Crossed by the TCP IPC server on
   `127.0.0.1:19284`. Treated as adversarial: any local process that
   can connect to localhost can attempt to send commands.
3. **Sidecar to third-party services.** Crossed over HTTPS to Gemini,
   exchanges, and the Cloudflare Worker. Treated as integrity-only
   against passive attackers and as a relying party that we trust.

## Threats and mitigations

### T1. Hostile process on the local machine sends IPC commands

A user's laptop runs many processes. Anything that can call
`socket.connect(("127.0.0.1", 19284))` would otherwise be able to call
`START_TRADING`, `EXECUTE_SKILL`, or `UPDATE_CONFIG` against our engine.

*Mitigation.* The IPC server requires a shared secret on every
request. The wire protocol is:

```
X-Auth-Token: <hex_token>\n
{"command": "...", "payload": {...}}\n
```

The token is a 32-byte value generated by the Rust shell at first
launch (`get_ipc_auth_token` command, see `src-tauri/src/lib.rs`),
stored in the OS keychain under service `money-machine` / account
`ipc-auth-token`. The Python sidecar reads it back via the `keyring`
package, or from the `IPC_AUTH_TOKEN` env var when running stand-alone
in tests or CI. Comparisons use `secrets.compare_digest` to avoid
leaking timing information.

Requests with a missing or invalid token are rejected with
`{"error": "...", "code": 401}` before the application command handler
is reached. Code path: `utils/ipc_server.py::_process_request`.

### T2. Bursty or runaway client exhausts the engine

Even an authenticated client can misbehave (a buggy frontend loop, a
malicious skill, a test that forgot to back off). Without limits the
engine can spend its event loop on IPC and starve trade execution.

*Mitigation.* A token-bucket rate limiter caps authenticated requests
at 100/s sustained with a 200-request burst. Excess requests get
`{"error": "Rate limit exceeded", "code": 429}`. Limits are tunable
per-instance for tests. Code: `utils/ipc_auth.py::TokenBucket`.

### T3. WebView is tricked into executing remote scripts

A Next.js page that ends up loading `<script src="https://evil/...">`
or an XSS injection through a chat-style component would normally have
full access to Tauri `invoke()`.

*Mitigation.* The Tauri webview runs with a strict CSP defined in
`src-tauri/tauri.conf.json`:

```
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: asset: https://asset.localhost;
font-src 'self' data:;
connect-src 'self' ipc: http://ipc.localhost
            https://oracle.axiomid.app
            https://aqt.axiomid.app
```

Inline scripts and remote scripts are blocked. `style-src` still
allows inline because Tailwind v4 and framer-motion ship inline
declarations during hydration; the next hardening pass will move
those to nonces. `connect-src` lists only the AlphaAxiom cloud
origins and the Tauri IPC channels.

### T4. Exchange credentials on disk

Exchange API keys and the upcoming wallet keystore are sensitive
long-lived secrets. Writing them to a dotfile in the repo or in the
home directory is the most common way users get drained.

*Mitigation.* The Rust shell exposes `store_api_key`, `get_api_key`,
and `delete_api_key` Tauri commands backed by the OS keychain (Apple
Keychain, Windows Credential Manager, libsecret/kwallet on Linux).
The Python sidecar reads only from environment variables it inherits
from its parent; `.env.example` documents this and explicitly tells
operators not to commit a populated `.env`.

### T5. Auto-updater pushes a malicious binary

The Tauri updater downloads release artifacts from GitHub. A
compromised release pipeline could ship a binary that exfiltrates
keys.

*Mitigation.* Updates are gated by a minisign public key embedded in
`tauri.conf.json::plugins.updater.pubkey`. Only artifacts signed by
the matching private key (held by release maintainers) are accepted.
Updater endpoints are pinned to
`github.com/Moeabdelaziz007/AlphaAxiom`.

## What this document does NOT cover yet

The next security passes will tighten the following, each gets its own
PR with tests:

- Sandboxing the Python sidecar (no FS access outside the app data
  directory).
- A least-privilege Tauri ACL: today the `default` capability inherits
  `core:default`, which is broader than necessary.
- CSP without `style-src 'unsafe-inline'` (requires nonce wiring in
  the Next.js export).
- Encrypted-at-rest local wallet keystore for on-chain trading.
- A kill switch IPC command that revokes the current token, terminates
  open trades, and disables further commands until restart.

## Reporting vulnerabilities

Open a private security advisory on the
[GitHub repo](https://github.com/Moeabdelaziz007/AlphaAxiom/security/advisories/new).
Do not file a public issue for sensitive findings.
